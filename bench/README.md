# bench/

评测脚本，保留作**方法参考**。

## 数据集不在此目录

所有脚本依赖作者本机的标注集与私有语料，其中标注集含真实卡片标题（个人内容），**不随仓库发布，也不对外提供**。没有对应数据时脚本无法直接运行。

| 脚本 | 需要什么数据 | 度量什么 |
|---|---|---|
| `eval-engineering.mjs` | `cases-engineering.json`（64 条人工标注，工程库） | top1 / top3 |
| `eval-precision.mjs` | PrecisionMemBench 数据集 | 断言式通过率 |
| `eval-wiki.mjs` | 法学 vault 副本或任意索引 | 概念名 recall、正文细节命中 |
| `eval-coderag.mjs` | CodeRAG-Bench `repoeval` 数据集（上游仓库下载） | nDCG@10 |

## 用于自测时

换成自己的标注集，格式见 `eval-engineering.mjs` 顶部注释：每条 `{ "q": "查询", "aliases": ["目标卡标题片段"] }`。

几点经验（来自本项目的实测）：

- **样本量 < 50 不下结论**。15 条时看到 +7pp，扩到 59 条变成打平
- **一次只改一个变量**，否则结论互相污染
- **评测输入必须与生产一致**：喂重排模型 40 字碎片会让结论反转 17pp
- **空断言是最强的断言**：「不该返回什么」比「该返回什么」更能暴露问题
