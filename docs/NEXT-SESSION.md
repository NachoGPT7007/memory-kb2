## 这次要验证的假设

2.2 的 M01/M02 低于官方 BM25 基线，是因为基线有「最近 6 轮原文」这条
不依赖检索的保底通道，而 kb2 没有。

## 实验方法：随机抽样 + 控制变量 + 配对对照

不要跑全量（¥13/次且慢）。按下面做：

1. **固定种子抽样**
   - 用固定随机种子（如 20261120）从 M01、M02 各抽 N 条 case
   - N 起步取 60，抽完把 case id 列表写进 eval/sample-<seed>.json 留档
   - 抽样脚本要能复现：同一种子必须抽到同一批题

2. **配对对照（paired）**
   - 同一批题跑 A（现状，窗口 0）与 B（最近 6 轮 + 检索，窗口 6）
   - 逐题配对比较，统计「A 过 B 没过」与「B 过 A 没过」的题数
   - 用 McNemar 检验或 bootstrap（2000 次，固定种子）给 95% 区间
   - 报告的是**配对差异**，不是两组各自的总分差——后者方差太大

3. **一次只改一个变量**
   - 这一轮只改 RECENT_WINDOW（0 → 6）
   - 不要同时动 limit、池深、rerank

4. **成本控制**
   - 60 条/榜约 ¥2.7/次，A+B 两组约 ¥5.4
   - 先跑 M02（差距更大，信号更可能显现），有信号再跑 M01

## 判定标准

- 配对差异 ≥ +3pp 且 95% 区间不含 0 → 采纳
- 差异在 ±2pp 内 → 视为无效果，停止这条线，去查「卡粒度」（一轮一卡 vs 事实级）
- 明确变差 → 否决，写入 ORIGIN 的功能账本

## 实验纪律（违反任何一条结论都不可信）

1. 一次只改一个变量
2. 样本量不到 50 不定结论；15 条上 1 条题的差距是噪声
3. 评测的输入必须与生产一致（第 16 轮：喂 40 字碎片给 rerank，结论反了 17pp）
4. 「空断言」是最强的断言（PrecisionMemBench 曾因跳过 shouldOnlyInclude: []
   把通过率从 13.2% 虚报到 44.7%）

## 附：这份提示词为什么这样写

| 设计 | 原因 |
|---|---|
| 先给已验证基线 | 新会话没有上下文，不给数字它会重新测一遍，浪费时间 |
| 明确「已否决」 | 防止它又去试多跳、BM25F 这些已经死掉的方向 |
| 随机抽样 + 配对 | 全量太贵；配对能消除题目难度的方差，比两组总分差敏感得多 |
| 判定标准事先写死 | 避免「跑完看到 1 分提升就采纳」的后见之明 |
| 先跑 M02 | 差距 5.9 分比 M01 的 2.7 分大，信噪比更高 |
| 明确「不要改内核」 | 窗口保底是组装层的事，改内核会让实验变量混在一起 |
